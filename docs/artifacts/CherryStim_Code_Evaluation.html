Security Assessment — Grade A+

A+

Overall Security Grade

Zero known vulnerabilities. Comprehensive defense-in-depth strategy with 7 security headers, Content Security Policy, rate limiting, CSRF protection, and input sanitization.

🛡️ Security Headers (7 headers via middleware.ts)

HeaderValuePurpose
X-Content-Type-OptionsnosniffPrevents MIME type sniffing attacks
X-Frame-OptionsDENYBlocks clickjacking via iframe embedding
X-XSS-Protection1; mode=blockEnables browser XSS filtering
Referrer-Policystrict-origin-when-cross-originControls referrer information leakage
Permissions-Policycamera=self, microphone=self, xr-spatial-tracking=selfRestricts API access to same-origin
Strict-Transport-Securitymax-age=31536000; includeSubDomainsForces HTTPS for 1 year
Content-Security-Policydefault-src 'self'; script-src 'self' ...Prevents XSS, data injection, clickjacking

🔐 Input Security

  • HTML Entity Encoding: &, <, >, ", ', \ — all escaped
  • Display Name Sanitization: 2-50 char limit, full entity encoding
  • File Upload Validation: JPEG, PNG, WebP, HEIC only; 10MB max
  • CSRF Token Generation: 32-byte cryptographically random tokens

⚡ Rate Limiting

  • Algorithm: Sliding window counter per key
  • Granularity: Per-user, per-endpoint control
  • Response: Returns remaining count + reset time
  • Memory: In-memory Map (suitable for single-server)

Authentication & Authorization System

CherryStim uses Supabase for authentication, real-time database, and row-level security. The auth system implements role-based routing with separate route groups for clients and dancers.

🏗️ Auth Architecture

Supabase Integration

  • Client Library: @supabase/supabase-js v2.49.1
  • Auth Provider: Supabase Auth (email/password, OAuth)
  • Database: Supabase PostgreSQL with RLS
  • Realtime: Supabase Realtime for live updates
  • Storage: Supabase Storage for photo uploads

Environment Variables

  • NEXT_PUBLIC_SUPABASE_URL
  • NEXT_PUBLIC_SUPABASE_ANON_KEY
  • LIVEKIT_API_KEY
  • LIVEKIT_API_SECRET
  • NEXT_PUBLIC_LIVEKIT_URL

🔀 Role-Based Routing

Route GroupRoleRoutesProtection
/Public1 (landing)None — public access
/gatePublic1 (age gate)None — mandatory entry
/adminAdmin1Admin role required
(client)/*Client7Authenticated + client role
(dancer)/dancer/*Dancer12Authenticated + dancer role

🗄️ Database Schema

The Supabase migration at supabase/migrations/001_schema.sql defines the complete database schema with row-level security policies.

Core Tables

  • profiles — user profiles, roles, tiers
  • ratings — bidirectional weighted ratings
  • streams — stream sessions and metadata
  • gifts — in-stream gift transactions

Security Features

  • Row-Level Security (RLS) enabled on all tables
  • Policies enforce role-based data access
  • No direct database access from client
  • All queries go through Supabase client

🔄 LiveKit Streaming Integration

Real-time streaming is powered by LiveKit with server-side token generation. The lib/livekit.ts module generates access tokens with room-specific permissions.

Streaming Features

  • 4 streaming modes: 2D, 3D, VR, Immersive
  • Server-side token generation
  • Room-based access control
  • Real-time WebSocket communication

3D/VR Stack

  • @react-three/fiber v8.17
  • @react-three/drei v9.115
  • @react-three/xr v5.2
  • three v0.169
