Server/Client Component Split

Server Components (default): Page-level route components use server rendering by default in Next.js 15 App Router.

Client Components ("use client"): All interactive components declare "use client" at the top — StreamViewer, StreamViewerLoader, VolumetricAvatar, GiftThrower, HapticsPanel, EmojiPicker, ChatInput, CoinBalance, Logo, NavHeader, all Zustand stores, admin dashboard, and page components using browser APIs.

SSR Fix: The StreamViewerLoader component (Platform branch) solves the @react-three/fiber SSR crash by dynamically importing StreamViewer inside a useEffect, ensuring Three.js Canvas only loads client-side.

CSP Analysis

Strengths

  • Default-src restricted to 'self'
  • Font sources limited to Google Fonts
  • Image sources explicitly whitelisted (self, blob, data, unsplash)
  • Media sources controlled (self, blob, GCS)
  • Frame-src restricted to self
  • Connect-src allows wss: for WebSocket (LiveKit) and https: for APIs

Improvement Opportunities

  • 'unsafe-eval' in script-src — needed for Next.js dev but should be removed in production
  • 'unsafe-inline' in script-src and style-src — consider nonce-based CSP for production
  • Broad https: in connect-src — should be narrowed to specific API domains in production

Input Validation Assessment

Rate limiting note: In-memory rate limiting resets on server restart. For production, consider Redis-backed rate limiting (e.g., Upstash) for persistence across serverless function invocations.

Auth Security

Supabase Auth: Session persistence enabled, auto-refresh tokens, service role key restricted to server-side seed script only. .env.example contains placeholder values. Risk: Seed script contains hardcoded passwords — these should be rotated before production deployment.

Recommendations

  • Server-side auth middleware: Add Supabase session validation in middleware.ts for route protection
  • Role claims in JWT: Store role in Supabase JWT custom claims to avoid extra DB query
  • Email verification: Enable email confirmation in production (currently auto-confirmed for seed users)
  • Password policies: Enforce minimum password strength beyond Supabase default
  • Rate limiting on auth: Add rate limiting to login/signup endpoints

Critical Rendering Path

Optimizations in Place

  • SSR/SSG: Next.js 15 App Router server components reduce client JS bundle
  • Dynamic imports: StreamViewerLoader lazy-loads the entire Three.js canvas
  • Font optimization: next/font/google for Cinzel + Playfair Display (automatic subsetting)
  • Image optimization: next/image with remote patterns for Unsplash
  • CSS: Tailwind CSS purges unused styles in production

Recommended Optimizations

  • Route-based code splitting for Three.js (only load on /stream/[dancerId])
  • Lazy-load Solana packages on wallet-related pages only
  • Implement React.lazy for heavy page components (admin dashboard)
  • Add next/dynamic for client-only components with ssr: false
  • Consider Zustand persist middleware for offline state
  • Implement ISR for semi-static pages (browse, equipment)

Overall Assessment

B+

Strong Foundation — Production-Ready with Identified Improvements

The CherryStim codebase demonstrates excellent architecture decisions (App Router, typed business logic, comprehensive Zustand state management), strong test coverage (367 tests across all modules), and thoughtful security implementation (7 headers + CSP + moderation engine). The primary gaps are server-side auth guards, production CSP hardening, and E2E test coverage. The business logic modules are exceptionally well-structured with clean type definitions and pure functions that are easy to test and maintain.
