Supabase Setup

Option A: Supabase Cloud (Recommended for Production)

  1. Create account at supabase.com
  2. Create new project (choose region closest to your users)
  3. Copy the Project URL and Anon Key from Settings → API
  4. Copy the Service Role Key (for seed script only — never expose to client)
  5. Navigate to SQL Editor and run the migration files

Option B: Local Supabase with Docker

# Install Supabase CLI
npm install -g supabase

# Start local Supabase (requires Docker)
supabase start

# Default local URLs:
# API:      http://127.0.0.1:54321
# Studio:   http://127.0.0.1:54323
# Inbucket: http://127.0.0.1:54324

Run Migrations

# Migration 1: Core schema (profiles, coin_wallets, dancer_profiles, transactions)
supabase db push

# File: supabase/migrations/001_schema.sql
# File: supabase/migrations/002_add_admin_role.sql

Schema Overview (001_schema.sql)

CREATE TABLE profiles (
  id uuid PRIMARY KEY REFERENCES auth.users,
  display_name text,
  role text CHECK (role IN ('client', 'dancer', 'admin')),
  tier text DEFAULT 'Pro',
  created_at timestamp DEFAULT now()
);

CREATE TABLE coin_wallets (
  user_id uuid PRIMARY KEY REFERENCES profiles(id),
  balance bigint DEFAULT 0
);

CREATE TABLE dancer_profiles (
  user_id uuid PRIMARY KEY REFERENCES profiles(id),
  bio text,
  gear_owner text DEFAULT 'cherrystim'
);

CREATE TABLE transactions (
  id uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
  from_user uuid REFERENCES profiles(id),
  to_user uuid REFERENCES profiles(id),
  amount bigint, type text,
  created_at timestamp DEFAULT now()
);

Seed Script Details (scripts/seed-users.ts)

The seed script uses the Supabase Admin API (service role key) to:

  1. Create auth user via supabase.auth.admin.createUser() with email auto-confirmation
  2. Upsert profile record in profiles table (id, display_name, role, tier)
  3. Upsert coin wallet in coin_wallets table (user_id, balance)
  4. For dancers: upsert dancer_profiles record (bio, gear_owner)

If a user already exists, the script fetches the existing user and updates their profile data.

LiveKit & External Services

LiveKit Setup

LiveKit provides real-time video/audio streaming for CherryStim's live performance feature. The platform uses both the server SDK (token generation) and client SDK (room connection).

1. Create LiveKit Account

  1. Sign up at cloud.livekit.io
  2. Create a new project
  3. Copy the API Key and API Secret from the dashboard
  4. Note the WebSocket URL (e.g., wss://your-project.livekit.cloud)

2. Environment Variables

LIVEKIT_API_KEY=your_livekit_api_key
LIVEKIT_API_SECRET=your_livekit_api_secret
NEXT_PUBLIC_LIVEKIT_URL=wss://your-project.livekit.cloud

3. Token Generation (lib/livekit.ts)

The createLiveKitToken() function creates access tokens server-side using livekit-server-sdk. Parameters: roomName, participantName, canPublish (dancers), canSubscribe (viewers). Throws error if LIVEKIT_API_KEY or LIVEKIT_API_SECRET are missing.

Solana Configuration

NEXT_PUBLIC_SOLANA_RPC_URL=https://api.mainnet-beta.solana.com
NEXT_PUBLIC_CHERRYSTIM_COIN_MINT=your_coin_mint_address

For development, use Solana devnet: https://api.devnet.solana.com

Vercel Deployment

Step 1: Connect Repository

  1. Sign in to vercel.com
  2. Click "New Project" → Import Git Repository
  3. Select the CherryStim repository
  4. Framework Preset: Next.js (auto-detected)
  5. Root Directory: ./ (default)

Step 2: Environment Variables

Add all environment variables in Vercel Dashboard → Settings → Environment Variables. Use separate values for Preview and Production environments:

GoDaddy DNS & Domain Configuration

DNS Records for Vercel

TypeNameValueTTLPurpose
A@76.76.21.21600Root domain → Vercel
CNAMEwwwcname.vercel-dns.com3600www subdomain → Vercel
TXT@(Vercel verification token)3600Domain ownership verification

GoDaddy Configuration Steps

  1. Log in to godaddy.com → My Products → DNS Management
  2. Remove any existing A records pointing elsewhere
  3. Add A record: @ → 76.76.21.21
  4. Add CNAME record: www → cname.vercel-dns.com
  5. In Vercel Dashboard: Settings → Domains → Add Domain
  6. Vercel will verify DNS and provision SSL certificate automatically
  7. Wait for DNS propagation (typically 5-30 minutes, up to 48 hours)

SSL/TLS Configuration

Automatic via Vercel: Let's Encrypt SSL certificate is automatically provisioned and renewed. Combined with the HSTS header (max-age=31536000; includeSubDomains) set in middleware.ts, all traffic is forced to HTTPS.

Post-Deployment Checklist

Pre-Launch Verification

  • All environment variables set in Vercel (both Preview and Production)
  • Supabase project created and migrations applied (001_schema.sql + 002_add_admin_role.sql)
  • Seed users created via npx tsx scripts/seed-users.ts
  • Admin login verified: timjackson2nd@gmail.com → redirects to /admin
  • Dancer login verified: goldenchiold@gmail.com → redirects to /dancer/dashboard
  • Client login verified: thebrucewaynejunior@gmail.com → redirects to /dashboard
  • LiveKit credentials configured and token generation working
  • DNS records configured and SSL certificate provisioned
  • All 367 tests passing (npm test)
  • Lint passing (npm run lint)
  • Production build succeeds (npm run build)
  • Security headers verified (curl -I or securityheaders.com)

Security Hardening

  • Rotate all seed user passwords from defaults
  • Enable Supabase Row Level Security (RLS) on all tables
  • Harden CSP: remove 'unsafe-eval' and 'unsafe-inline', implement nonce-based CSP
  • Narrow CSP connect-src to specific API domains
  • Set up Supabase email confirmation for production (disable auto-confirm)
  • Configure rate limiting with Redis (Upstash) for production scale
  • Set up Sentry or similar for error monitoring
  • Configure CORS headers for API routes

Monitoring Setup

  • Vercel Analytics enabled for Web Vitals monitoring
  • Supabase Dashboard monitoring for database performance
  • LiveKit Dashboard for streaming quality metrics
  • Error tracking (Sentry) for runtime error capture
  • Uptime monitoring (UptimeRobot, Pingdom, or similar)
