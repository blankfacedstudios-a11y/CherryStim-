Anti-Abuse Mechanics

detectBadRatingPattern() Algorithm

  1. Filter all ratings given by user in the last 30 days
  2. If fewer than 5 ratings → no pattern detected (insufficient data)
  3. Calculate average score across recent ratings
  4. If average < 40 → bad pattern detected
  5. Add user to blockedClientIds Set
  6. All future rating attempts by blocked user are silently rejected
  7. Block persists for 14 days (configurable via clientBadPatternBlockDays)

KYC/AML Compliance — Card Program

The CherryStim Card Program requires full Know Your Customer (KYC) and Anti-Money Laundering (AML) compliance as mandated by the Bank Secrecy Act (BSA), USA PATRIOT Act, and FinCEN regulations.

Transaction Monitoring

  • Suspicious Activity Reporting (SAR): Automated detection of unusual patterns — rapid deposits/withdrawals, round-number transactions, geographic anomalies
  • Currency Transaction Reporting (CTR): Mandatory reporting for cash transactions exceeding $10,000
  • Structuring Detection: Pattern recognition for transactions designed to evade reporting thresholds
  • Velocity Checks: Rate limiting on transaction frequency per card per time window

Card Program KYC Flow Integration

KYC is integrated into the dancer onboarding flow (Step 6 in the Launch Roadmap). The automated pipeline:

  1. Dancer applies for card during onboarding (Step 3: "CherryStim Card Selection")
  2. Identity verification via integrated KYC provider (Plaid/Socure/Jumio)
  3. SSN validation and credit bureau check
  4. OFAC/SDN/PEP screening
  5. Address verification via USPS
  6. Card approval or manual review queue
  7. Card manufacturing trigger to CARDMAKER
  8. Fulfillment via welcome package shipping pipeline

Credit Bureau Reporting — Metro 2 Format

All three card tiers report on-time payments to Equifax, Experian, and TransUnion. Compliance requires:

  • Metro 2 Format: Industry-standard credit reporting format maintained by CDIA (Consumer Data Industry Association)
  • Data Furnisher Agreement: Formal agreements with each bureau (Step 5 in Launch Roadmap, 8-12 week process)
  • Monthly Reporting: Automated monthly data submission including account status, balance, payment history
  • Dispute Resolution: FCRA-compliant dispute handling within 30-day investigation window
  • Accuracy Requirements: Regular data quality audits per FCRA Section 623

Biometric Data Considerations (AR Filters)

Critical compliance area: The AR filter engine processes 240-point face mesh data, lip sync, eye gaze, facial expressions, body pose, and hair/skin segmentation. Under GDPR Article 9 (special categories — biometric data) and BIPA (Illinois Biometric Information Privacy Act), this requires:

  • Explicit informed consent before first filter activation
  • Data processed on-device where possible (Banuba SDK local processing)
  • No persistent storage of biometric templates
  • Real-time processing only, discarded after stream ends
  • Written policy on biometric data retention (required under BIPA)

Data Residency

Supabase deployment region selection ensures EU user data remains in EU data centers. US card program data stored in US. Dubai expansion requires UAE data residency per DIFC Data Protection Law.

PCI-DSS Compliance

The CherryStim Card Program requires Payment Card Industry Data Security Standard (PCI-DSS) compliance for handling cardholder data.

PCI-DSS Scope

CherryStim's compliance approach: Minimize PCI scope by leveraging BaaS partners (Marqeta/Galileo) who hold Level 1 PCI-DSS certification. CherryStim never directly stores, processes, or transmits full card numbers (PAN). Tokenization through the partner API ensures cardholder data never touches CherryStim servers.

Tokenization Flow

  1. Dancer enrolls in card program via onboarding
  2. KYC verification triggers card creation via Marqeta API
  3. Marqeta generates card and returns token (not PAN)
  4. Token stored in CherryStim database (Supabase)
  5. All transaction display uses last 4 digits only
  6. Apple Pay / Google Pay use device-level tokenization

All routes except static assets are protected by the Next.js middleware (middleware.ts) which injects 7 security headers on every response. The middleware matcher pattern /((?!_next/static|_next/image|favicon.ico|logo/).*) ensures universal coverage.

Rate Limiting

checkRateLimit(key, maxRequests, windowMs) implements an in-memory sliding window rate limiter. Returns { allowed: boolean, remaining: number, resetAt: number }. On window expiration, the counter resets. Map-based storage keyed by IP/user/endpoint combinations.

CSRF Protection

generateCSRFToken() creates 32-byte (256-bit) cryptographically random hex tokens using crypto.getRandomValues() with fallback to Math.random() for non-browser environments.

Permissions Policy

The Permissions-Policy header restricts sensitive hardware APIs to same-origin only:

  • camera=self — Camera access restricted to CherryStim domain (needed for AR filters and streaming)
  • microphone=self — Microphone for live audio streaming
  • xr-spatial-tracking=self — WebXR spatial tracking for VR/Immersive modes

This prevents third-party iframes or scripts from accessing device hardware.
