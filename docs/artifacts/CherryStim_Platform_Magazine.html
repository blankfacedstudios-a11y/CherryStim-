About CherryStim

CherryStim is a premium immersive entertainment platform that bridges the gap between traditional 2D live streaming and the future of volumetric, VR, and haptic-enabled interactive experiences. Built on Next.js 15 with the App Router, React 18, TypeScript strict mode, and a full Three.js/WebXR immersive stack, the platform delivers four distinct experience modes from any device.

Mission Statement

"To create the world's most luxurious and technologically advanced live entertainment platform, empowering performers with financial tools, career advancement, and cutting-edge immersive technology."

Platform Architecture

The platform spans two development branches: the Platform branch (cursor/cherrystim-immersive-platform-bf9b) containing the original scaffold with Supabase auth, login/signup, NavHeader with role-based navigation, admin dashboard, SVG/PNG logos, SSR fix for @react-three/fiber via StreamViewerLoader, 2 Supabase migrations, config.toml, and seed.sql; and the Dev Environment branch (cursor/setup-dev-env-48c2) with massive feature expansion including 23 routes, 367 tests across 40 test files, and all major business systems.

Three User Roles

🎭 Dancer (Performer)

Content creators with 13 dedicated routes, onboarding, welcome packages, streaming setup, Star Bright Lights casting, SAG pipeline, card program, filters, equipment management, and order tracking.

👁️ Client (Viewer)

Premium viewers with 8 routes including browse, stream viewing, dashboard, profile, filters, onboarding, and order tracking. Experience modes from 2D classic to full immersive with haptics.

🛡️ Admin

Full platform management via the /admin dashboard with 6 tabs: Overview stats, Card Program management, Dancer Packages, Client Packages, Order Management, and Launch Roadmap. Role-based routing directs admin users to /admin on login.

Stream Viewer Architecture

The stream viewer is a multi-layer composition:

Authentication System

CherryStim uses Supabase Auth with email/password authentication, role-based routing, and a comprehensive user seeding system. The auth system spans both development branches.

Login Page (/login)

Dual-mode form supporting both Sign In and Sign Up with role selection. On sign-up, the system creates:

  • Auth user via supabase.auth.signUp() with user_metadata (display_name, role)
  • Profile record in profiles table with role and tier
  • Coin wallet in coin_wallets table (initial balance varies by role)
  • Dancer profile in dancer_profiles table (for dancer role) with bio and gear_owner

Rating System

CherryStim implements a weighted rating system with anti-abuse mechanisms, defined in lib/ratings.ts and managed via the useRatingStore Zustand store.

Core Configuration

Dancer→Client Weight1.0Dancer ratings of clients carry full weight

Low Rating Penaltylimited_accessLow-rated clients get restricted platform access

Weighted Rating Calculation

The computeWeightedRating() function applies asymmetric weights: when clients rate dancers, each vote counts at only 0.25 weight — meaning a single dancer's vote on a client equals 4 client votes on a dancer. This protects performers from rating manipulation. New users start at 100.

Anti-Abuse: Bad Pattern Detection

detectBadRatingPattern() analyzes a user's last 30 days of ratings. If they've given 5+ ratings with an average score below 40, the system auto-blocks them from rating for 14 days. The useRatingStore maintains a blockedClientIds Set and rejects new ratings from blocked users.

Dancers with ratings below 75 receive reduced visibility in search results and browse pages. This incentivizes consistent quality without hard-banning performers. The getDancerVisibility() function returns "full" or "reduced".
